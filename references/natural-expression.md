# 整体自然表达：从原片到最终交付

人物对白、采访、互动剧情、有原视频的改造，以及业务反馈慢动作、站桩或丢细节时执行。目标是观众在正常速度下看懂人物为何反应、动作如何发生、下一镜为何出现。文案正确、画面清楚和文件能播放是必要条件，不能代替这项验收。

## 一、先明确改什么、保留什么

有原片时先锁定目标范围，在原速下观察完整互动，再在疑点处慢放或密集取帧。对照对象是对应动作/台词事件，不是把两个不同长度的视频均匀抽六张图。只有截图时不声称掌握原片动作；若任务明确要求按原片还原，缺少原片时应说明限制并请求必要素材。

先按 [制作约定](production-contract.md) 锁定改造范围、造型、原片表演依据与实际模型条件。建立一份可复用的镜头事件表，直接放进本需求分镜，不另复制多份相同清单；关键问答补入逐角色交流目的、信息变化、语气与反应，复杂动作补入路径、传力与镜头变化：

| 原片时间/事件 | 必须保留的细节 | 本次允许修改 | 生成镜头与使用区间 | 实际结果/差异 |
|---|---|---|---|---|
| 一次完整问答或接触周期 | 谁先动、谁回应、视线、手/道具、速度变化、反应和切点 | 用户指定的文案/产品/角色等 | shot_id、对应原片范围、生成时长与预计使用时长 | 通过证据，或缺失/待复核 |

原片的机位、动作方向、接触次序、反应、出入场、道具持握、身份标签、包装和收尾，不能因为文字需求没逐项重写就忽略。按已选制作模式区分不变量与优化项：一比一保留指定细节，投流改编可优化角色及具体表演/镜头，但关键反应的触发、创意机制和需求信息不能丢失。需要新设计的部分明确标为新设计；做不到的关键项不能用“风格相近”代替。具体检查见 [reference-fidelity.md](reference-fidelity.md)。

## 二、分别判断三种“慢”

| 表现 | 先核对证据 | 修整方向 |
|---|---|---|
| 播放或导出变慢 | 播放器 playbackRate、原片/交付时间戳与时长、解释帧率、setpts/atempo、重复帧或加载停顿 | 修正错误的时间映射/播放设置，保留声画同步；记录修正前后 |
| 动作本身像慢镜头 | 对齐同一事件的起动→接触/峰值→回位，比较参考与候选的真实用时、速度变化和身体承重 | 按原速动作重做；缩短空等待不能修复缓慢的伸手/转头本体 |
| 剪辑拖沓或接话不顺 | 开口前后等待、句间停顿、重复动作、静止尾巴、反应与对白关系、实际切点 | 保留有效反应，剪掉无信息停留；缺承接则补镜，跨镜声音另标来源 |

24fps、播放器1倍速、总片长变短、镜头变多，都不能证明人物动作自然。全帧光流也不能证明肢体活跃：镜头推近或背景动可能制造运动量。比较同一动作，景别不同时按主体尺度判断，不能用全片平均时长或万能速度阈值代替。

记录关键事件在参考和候选中的实际时间范围、停顿位置和差异原因。原片若本来是慢动作/夸张动画，应保留其风格；新台词更长时给正常语速足够时间，必要时增加有依据的承接画面，不把同一个短动作慢慢拉满对白长度。生成时长只为容纳动作、对白和剪辑余量，不是最终每镜必须用满的时长。

规划时分别确定交流意图和时长预算：增加“投入分享、惊喜”等语义不保证改变实际说话速度。用当前文案及参考事件估算，不直接继承上一失败版的秒数；为对照实验保留旧时长时明确记录。较短试片仍须检查完整对白、句尾和意外画面内容，不能因语速接近参考就判整片合格，也不把某次5秒/7秒试验结果固定成默认时长。

先修生成动作，再修剪辑。禁止用整片倍速、插帧、重复帧、冻帧或强锐化掩盖表演问题。仅对确有意图且不损害声音、动作因果与清晰度的局部变速使用时间重映射，并逐段检查；不把一个倍速值作为默认修复方案。反打/J-L切须使用真正适配的听者反应，不能拿正在说另一句台词的画面冒充倾听。连续与切镜的规则见 [segment-continuity.md](segment-continuity.md)。

## 三、人物表演按交流意图设计

按 [制作约定的表演规划](production-contract.md#2-先设计交流目的再设计表情) 在生图前确定人物目的、状态和语气。给角色一个正在完成的交流任务，例如“让采访者理解这次体验为何打动她”，而不是“抬眉一次、摇头一次、最后笑开”。可见反应是表达这个目的的方法，不能反过来为凑动作编造回忆、疑问和停顿。

- **说话者**：重音、节奏和表情表达同一意思。回忆不必低头寻找，强调不必点头，惊喜不必张嘴瞪眼；根据本角色和参考选具体方案。一个意群不等于一次表情切换，允许在讲话中逐渐变化、保持投入或轻松收住。
- **听者**：听话本身有目的，可以求证、判断或等待某个信息；反应可与对方对白重叠，有决定性信息才发生相应转变。不安排每句一次点头或统一延迟，不提前演出尚未获知的结果；嘴不跟读。
- **身体**：让手势、头肩、躯干与话语或实际道具操作相随，而非依次执行各部位动作。保持安静也可以可信，不能为了“有身体参与”强加晃肩、前倾或摊手。坐姿、持物和支撑关系必须成立，运动协调不同于运动量大。
- **情绪方向和强度分别确定**：愉快的惊喜不等于怀疑，亲密分享不等于播报式兴奋。依参考、台词和角色气质明确方向；有吸引力的表演可以鲜明，也可以克制，不用每句递增、每镜峰值或结尾大笑作为默认结构。风格化角色需要夸张时保留其幅度和事件因果。
- **时间是连续的**：目光、声音和姿态可自然交叠、先后呼应，不要求所有部位在同一重音同步启动/停止，也不机械串成“转头完成后才笑、笑完才开口”。对白之外仅留有交流用途的余量，不能为预设动作填空或加慢动作。

对“多年没这么心动、打开新世界”的街访，一种可选设计是：受访者已被体验打动，愿意向采访者解释这种久违的新鲜感；中间回顾带个人感受，末句把喜悦分享出去。是否移开目光、扩大笑容、如何收尾由具体表演依据决定，不能把这句文案强制翻成“先回忆摇头，随后抬眉，最后大笑”。这只是语义设计例，不是已观察到的原片动作，也不适用于所有采访。

将业务反馈分开处理，再修改计划和实际条件：

| 反馈所指问题 | 生成前优先修什么 |
|---|---|
| 情绪太淡、重点读不出来 | 明确缺失的态度或转折、语音重音与观众应读到的反应；母图和景别是否支持，不直接全程加强表情 |
| 有表情但僵硬、像按指令做动作 | 查交流目的是否空泛、是否串行编排部位动作、是否强制固定笑容/姿态、声音与动作是否脱节；不继续加动作数量 |
| 表情方向错或提前反应 | 修人物获知信息的时间、词义歧义与开场母图；例如自信入场不能提前做被嫌弃后的垮脸 |
| 太用力、假笑或重复晃动 | 去掉无动机的峰值、循环和每句小动作，让关键反应保持可读；不退回全程只动嘴 |

例如飞机对话的“有多持久？”是求证，“听起来不便宜吧？”转向价格判断，不应套同一种礼貌微笑；具体身体反应取自原片或明确的改编设计。对照反馈对应版本和原片，检查语义、幅度、时机及声画呼应。抽帧里有笑容和ASR正确不能证明问题已解决；详细诊断见 [natural-performance.md](natural-performance.md)。

## 四、让工作流真正支持设计

把母图作为这场表演可开始的一刻来设计：开场状态、交流视线、姿态和所需操作空间与计划一致，景别能读到关键表情/动作，身份与材质清晰。没有要求时不先做统一正脸海报、大笑照或中性站姿再要求视频强行转戏。已认可母图能支持当前意图就复用，返修不自动换人重绘。检查提交图中真正连入的条件，而不是只数 LoadImage 节点。

独立镜头通常不绑相同首尾帧；连续组用实际合格边界，尾帧指定动作落点，不把每段拉回开场。两张不同首尾图也不保证运动正确。静态图片约束外观和状态，不提供原片的表演时序、呼吸与语气；明确要保留细腻原表演时，规划阶段先评估可用视频/音频条件，而非图生失败后才想起原片。核对实际节点用途：声音身份参考不一定锁语速情绪，音频驱动也不等于控制全身动作。仅有图条件的路线可用于获准原创表演，但保真能力须如实标明，不能声称参考视频已接入或表演已复刻。

提示词保留身份、空间、交流意图、关键变化和必要物理过程。用意群定位真正需要的转折，不预设“开头确认／中段回想／末句惊喜”模板；完整台词集中在Dialogue中，避免在动作说明反复引用整句。保持六段式，把声线与语气写在Sound，Action不再重复排一套脸部节拍。精简表情编排不能删掉抓取、接触、脚步、动作方向或旁白归属等必须精确的事实。

避免无依据的 slow、slowly、dreamy、floating、ceremonial 或所有动作为 gentle/subtle 的叠加；这些词只在参考确实需要时使用。camera steady 约束机位，不约束人物。不用正则命中“自然/意图”等词或字段齐全替代设计判断；后续质检用于发现实际偏差，不替代第一稿的表演设计。

## 五、先验证完整互动小节，再扩展

高风险试片覆盖本次适用的说话者/听者、有声与无声反应及相关身体/道具；有切镜或技术分段才必须覆盖相应接点，单镜任务不为验收人为增加切点。动作接对白须联合验证，不能以分别做成了无声动作和口播代替。先验整段“触发→回应→动作/结果”，不能只用一句单人台词或漂亮首帧宣布方案通过。试片使用最终计划的原生尺寸与质量，不用低配通过后假设高配自然解决。

可比试验一次优先改变一个主要变量，记录母版、提示词、条件类型、种子、长度、质量参数和实际差异。对不同镜头不机械要求同一种动作。生成出合格图片、无语音动作或一条对白，都不能代替其他能力的试产。相同问题三次失败后换方法/参考/可剪辑结构，不能只不断换种子；改变方法仍达不到关键要求时，依用户授权跳过并明确原因，不降低标准计为完成。

## 六、整条交付的共同门槛

每个最终版本保存一份 `production_review.json`（或现有同等QA清单），关联需求ID、版本、原片/成片路径和SHA、实际prompt_id，至少独立给出以下结论与具体时段证据：

1. `reference_fidelity`：事件表每项保留/授权修改/缺失，关键细节没有无依据消失；无原视频的已授权原创注明适用范围。
2. `pacing_and_continuity`：原速关键动作及最终整片接点/停顿已检查，区分生成动作速度与剪辑停留；不能只列帧率与总时长。
3. `performance`：逐角色检查表情、身体协调、说/听互动，观众能读到符合内容的变化；近景清晰不代表表演通过。
4. `dialogue_and_quality`：完整文案、声画归属、句尾、产品身份与展示、原生清晰度和全片解码分别合格。

每项状态用 pass / fail / needs_review / 有理由的 not_applicable，并给证据路径和时间范围。动态检查注明实际观看方式、正常播放速度、观察内容和结论；静态图、ASR、播放器自动播到结束各自只能证明其覆盖内容。当前工具只能看抽帧或静音自动播放时，如实标明动态表演/原声检查未完成，不把证据路径存在等同于质量证明。

任一适用项 fail 或 needs_review 时，不得宣称生产验收通过。已知动作、角色、商品等失败先修复，不算合格交付。仅在当前用户允许候选交付时，文件与技术检查齐备且无已知关键失败的版本可作为“已生成·待业务审片”预览；如动态/原声能力不足，如实保留 needs_review 和缺失证据，不为此伪填 pass 或逐段等待确认。其他不依赖失败条件的镜头继续工作。

完整候选预览按 [workbench-sync.md](workbench-sync.md) 的可选集成约定处理；已具备全部生产验收证据的版本再运行下述严格检查并声明验收通过。业务待审不等于生产通过，文件上传/网页播放也不能反向改变质量结论。

收到负面业务反馈时关联具体版本和反馈来源，撤销该版本地完成信号，保留原片及人工审片记录；只暂停同一失败方案尚未运行的受影响任务，已运行结果作为候选保留。修正代表片通过再扩展。更新本skill并不等于旧视频已重做或质量已改善。

## 人物需求声明生产验收通过前的证据检查命令

对人物需求，将现有QA整理成下列结构后运行；文件为相对于review文件的路径或绝对路径。`clips`逐项复制当前交付清单的file、sha256、prompt_id，清单文件路径相对于manifest。原片、成片和证据均使用当前版本实际SHA。

```json
{
  "request_id": "当前需求ID",
  "revision": "当前版本",
  "has_reference_video": true,
  "unresolved_feedback": [],
  "clips": [{"file": "materials/实际片段.mp4", "sha256": "实际SHA", "prompt_id": "实际任务ID"}],
  "full_preview": {"path": "edited/实际完整预览.mp4", "sha256": "实际SHA"},
  "roles_reviewed": [{"role": "角色名", "speaking_or_listening": "说话/倾听的实际区间", "observed_behavior": "实际观察，不是提示词计划", "time_ranges": [[0, 3]]}],
  "checks": {
    "reference_fidelity": {"status": "needs_review", "observations": "", "evidence": []},
    "pacing_and_continuity": {"status": "needs_review", "observations": "", "evidence": [], "dynamic_review": {}},
    "performance": {"status": "needs_review", "observations": "", "evidence": [], "dynamic_review": {}},
    "dialogue_and_quality": {"status": "needs_review", "observations": "", "evidence": []}
  }
}
```

检查完成后，各项evidence填实际记录的path/sha256；两项dynamic_review记录method=direct_normal_speed_observation、playback_rate=1、reviewer（实际观察者/方式）、full_preview_sha256、time_ranges。示例默认待复核，不能把模板填满当作完成检查。无原视频且已获准原创时，reference_fidelity可用有reason的not_applicable；人物表演不可因此跳过。

```bash
python <skill>/scripts/check_production_review.py --review <本需求/production_review.json> --manifest <本需求/delivery_manifest.json>
```

退出2表示缺失、失败或版本/文件不匹配，保持生产验收未通过；退出0只表示证据结构与当前文件一致，不判断表演真假和自然度，不自动发布。实际完整观看和四项验收仍由执行者完成。已有项目的ASR/contact/browser记录不满足结构时，补做缺少的观察，不能批量填pass迁移旧结论。无人物的纯产品任务按自身动作/产品验收，不机械调用人物专用门槛。
